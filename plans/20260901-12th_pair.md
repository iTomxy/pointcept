# Auditing Errors on the 12th Rib Pair

## Problem

I am studying three kinds of error related to the 12th rib pair in PTv3
predictions on the Ribsegv2 test set:

1. Foreground-background confusion:
   - vol. 562: the annotated 12th rib pair is predicted as background;
   - vol. 608: an inferior vertebral/background candidate is predicted as the
     12th rib pair.
2. Rib-label confusion: a true rib is predicted as another rib. An inferior
   candidate receiving the terminal label may cause an ordinal shift of the
   true terminal rib, as in vol. 608.
3. Broken prediction integrity: different parts of the same GT rib receive
   different predictions.

The label-accuracy metric based on `recall > 70%` from the Ribsegv2 paper
(`rib_label_acc` in [pointcept/utils/eval_cm.py](../pointcept/utils/eval_cm.py))
does not distinguish these failures. I therefore need per-class auditing for
the two terminal rib labels, classes 12 and 24.

## Neighbor Definition

For rib label `i`, both `i - 1` and `i + 1` are neighbors when those labels
exist on the same side of the rib cage. The edge between classes 12 and 13 is
removed because class 12 is the bottom rib on one side while class 13 is the
top rib on the other side.

Equivalently, start with adjacent labels in `1..24` and remove the pair
`{12, 13}`. In particular:

- `neighbors(12) = {11}`;
- `neighbors(13) = {14}`;
- `neighbors(24) = {23}`.

## Per-Class Metrics

Let `C[y, p]` be the confusion-matrix count for GT label `y` and predicted
label `p`. For each audited class `c` in `{12, 24}`, calculate two directional
decompositions.

GT-conditioned errors, with denominator `sum_p C[c, p]`:

1. `recall = C[c, c] / sum_p C[c, p]`;
2. `bg_miss = C[c, 0] / sum_p C[c, p]`;
3. `neighbor_out = sum_{n in neighbors(c)} C[c, n] / sum_p C[c, p]`;
4. `other_rib_out`: the remaining fraction predicted as non-neighbor ribs.

Prediction-conditioned errors, with denominator `sum_y C[y, c]`:

1. `precision = C[c, c] / sum_y C[y, c]`;
2. `bg_contamination = C[0, c] / sum_y C[y, c]`;
3. `neighbor_in = sum_{n in neighbors(c)} C[n, c] / sum_y C[y, c]`;
4. `other_rib_in`: the remaining fraction contributed by non-neighbor ribs.

`bg_contamination` is used instead of the conventional background FPR because
the very large background denominator would make FPR difficult to interpret.
Metrics with a zero denominator should be reported as missing rather than
zero. GT-absent but predicted terminal classes should be audited separately.

For prediction integrity, report all of the following together:

1. `integrity`: among GT-class points receiving a non-background prediction,
   the fraction assigned to the dominant predicted rib label;
2. `dominant_prediction`: that dominant label;
3. the non-background prediction distribution used by integrity;
4. the number of recognized points used as the integrity denominator.

Background predictions are excluded because they are foreground misses, not
rib-label fragmentation. A GT rib predicted entirely as background therefore
has undefined integrity and belongs only to the `bg_miss` stratum. Integrity
still measures concentration rather than correctness: a whole rib predicted
as one neighboring rib has integrity 1.0 despite having zero recall.

## Hypotheses

1. Volumes with 11 long rib pairs and an extremely short, questionable GT
   terminal pair tend to have high `bg_miss`, with background dominating the
   full prediction distribution. This is a dataset-relative FN but may
   represent an anatomically reasonable rejection of an ambiguous annotation.
2. Volumes with 12 normal-length rib pairs plus an inferior background
   candidate tend to have high terminal-class `bg_contamination`.
3. Assigning the terminal label to an inferior candidate may cause the true
   terminal rib to be predicted as a neighboring rib. For terminal classes 12
   and 24, every current case with integrity below 0.95 is a subset of
   `neighbor_out`, with no non-neighbor rib confusion. This supports treating
   terminal-class low integrity as a severe adjacent-label split rather than as
   an independent failure mode. A coherent whole-rib shift can still have
   integrity 1.0, so `neighbor_out` remains the more general metric.
4. Near-spine foreground-background confusion common to many ribs is a second
   anatomical mechanism to audit. It is spatially local and should not count
   as an integrity failure after background predictions are excluded.

## Error Types and Candidate Mechanisms

The observable error types are:

1. terminal-rib FN: GT class 12 or 24 predicted as background;
2. terminal-label FP: GT background predicted as class 12 or 24;
3. rib-label confusion: a terminal rib predicted as another rib, or another
   rib predicted as the terminal label. Severe splitting is the low-integrity
   subset of this type.

These error types do not map one-to-one to their possible causes. The current
visual audit suggests at least two mechanisms:

1. Terminal rib-versus-transverse-process ambiguity. A very short inferior
   candidate may be annotated as the 12th rib when only 11 normal pairs are
   present, but left as background when 12 normal pairs are already present.
   Depending on the annotation and model decision, this can appear as a whole
   terminal-rib FN, an inferior FP, an adjacent-label shift, or split-label
   integrity failure.
2. Near-spine attachment-zone ambiguity. The rib root and adjacent vertebral
   structures are locally difficult to separate, producing short FN or FP
   regions at the medial end. This occurs at non-terminal ribs as well, so it
   is a general boundary/localization problem rather than evidence of failure
   to identify the 12th pair.

The current scalar confusion metrics distinguish the three error types but
cannot establish the second mechanism spatially. That requires checking where
the erroneous points occur, for example by measuring errors in a medial or
rib-root region separately from the rest of each rib.

## Audit Strata

Classes 12 and 24 should be ranked independently within each stratum:

1. highest `bg_miss`: 562-like terminal-rib dropout;
2. highest `bg_contamination`: background hallucinated as the terminal rib;
3. highest `neighbor_out`: terminal rib shifted to an adjacent rib label;
4. integrity below 0.95 among GT ribs with at least one non-background
   prediction: genuinely split or fragmented recognized terminal-rib points.
   Minor non-background label spill with integrity near 1.0 is excluded; the
   threshold is configurable with `--integrity-threshold`;
5. GT terminal class absent but predicted: explicit hallucination cases;
6. smallest good controls: terminal ribs with the lowest GT point counts among
   cases with high recall, precision, and integrity. GT point count is only a
   proxy for anatomical rib size.

The first five strata provide bad-case lists. The controls make it possible to
compare failures with similarly small terminal structures that the model
handles correctly. These lists should be used for a stratified visual audit
rather than collapsed into one unified severity score.

Generate the audit tables for every split with:

```bash
python tools/audit_rib_classes.py \
  --experiment-dir exp/ribsegv2/final \
  --split train \
  --classes 12 24

python tools/audit_rib_classes.py \
  --experiment-dir exp/ribsegv2/final \
  --split val \
  --classes 12 24

python tools/audit_rib_classes.py \
  --experiment-dir exp/ribsegv2/final \
  --split test \
  --classes 12 24
```

The long-form per-class CSV is intended to support a later Matplotlib report,
while the per-stratum CSV files provide the volumes to inspect manually. The
default output is
`exp/ribsegv2/final/reports/rib_class_audit/<split>/`; use `--output-dir` to
change the destination.

Draw normalized, side-by-side train/validation/test histograms with:

```bash
python tools/plot_rib_class_audit.py \
  --report-dir exp/ribsegv2/final/reports/rib_class_audit
```

This writes one chart per stratum under `rib_class_audit/plots/`. Each chart
contains separate class-12 and class-24 panels. Within every histogram bin,
the train, validation, and test bars are adjacent rather than stacked. Bar
heights are percentages of eligible volumes so the unequal split sizes remain
comparable; each panel also reports the selected/eligible volume counts.

## Integrity Across All Ribs

To find other causes of integrity failure, scan all 24 rib labels while keeping
the same background-excluded definition and the 0.95 threshold:

```bash
python tools/audit_all_rib_integrity.py \
  --experiment-dir exp/ribsegv2/final \
  --splits train test
```

This writes one detailed row per affected rib class to
`low_integrity_all.csv` and one compact row per affected volume to
`low_integrity_volumes.csv`, under
`exp/ribsegv2/final/reports/rib_integrity_all_ribs/<split>/`.

For the current predictions, the train split has three affected volumes:
334 (class 8), 218 (class 11), and 217 (class 17). All three involve an
adjacent rib label.

The test split has 50 affected rib-class cases in 23 volumes:
570, 598, 507, 539, 593, 524, 608, 589, 549, 546, 556, 557, 659, 519, 594,
526, 620, 582, 639, 613, 578, 503, and 602, ordered by their minimum integrity.
Of the 50 class cases, 48 include neighbor-out confusion. The only cases with
no neighbor-out are classes 3 and 4 in vol. 570, and all five class cases with
non-neighbor confusion occur in vol. 570. This makes vol. 570 the clearest
candidate for an integrity mechanism unrelated to ordinary adjacent-rib or
terminal-rib shifting.
